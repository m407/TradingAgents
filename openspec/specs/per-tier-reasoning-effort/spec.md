# Спецификация per-tier-reasoning-effort

## Purpose

Позволить независимо управлять уровнем усилий модели при рассуждении для deep и quick, сохраняя действующие общие настройки провайдера и выбор моделей.

## Requirements

### Requirement: Независимые настройки двух типов

Система SHALL поддерживать необязательные Python-ключи `deep_think_reasoning_effort`, `quick_think_reasoning_effort` и соответствующие переменные окружения `TRADINGAGENTS_DEEP_THINK_REASONING_EFFORT`, `TRADINGAGENTS_QUICK_THINK_REASONING_EFFORT`. Значения по умолчанию SHALL быть `None`; отсутствие ключа, `None` и пустая строка SHALL означать наследование, а не отключение reasoning.

#### Scenario: Разные значения из окружения
- **WHEN** для OpenAI заданы deep=`high` и quick=`low` через новые переменные окружения
- **THEN** deep использует `high`, а quick использует `low`

#### Scenario: Программная конфигурация
- **WHEN** Python-конфигурация задаёт разные значения новых ключей
- **THEN** каждый тип использует собственное значение так же, как при настройке через окружение

### Requirement: Независимое наследование общего значения

Система SHALL разрешать reasoning отдельно для каждого типа в порядке: непустое значение типа, непустая существующая настройка фактического провайдера этого типа, отсутствие параметра в запросе. Общими настройками SHALL оставаться `anthropic_effort` для Anthropic, `google_thinking_level` для Google и `openai_reasoning_effort` для OpenAI, существующих OpenAI-совместимых провайдеров и Azure. Изменение провайдера одного типа SHALL NOT менять разрешение reasoning другого типа.

#### Scenario: Переопределён только deep
- **WHEN** deep=`high`, quick не задан, обе модели используют OpenAI, а общая настройка OpenAI равна `medium`
- **THEN** deep использует `high`, quick использует `medium`

#### Scenario: Переопределён только quick
- **WHEN** quick=`low`, deep не задан и общая настройка соответствующего провайдера не задана
- **THEN** quick использует `low`, а для deep параметр reasoning не отправляется

#### Scenario: Существующая конфигурация
- **WHEN** индивидуальные настройки reasoning и провайдера отсутствуют, но общая настройка активного провайдера задана
- **THEN** оба типа используют эту общую настройку

#### Scenario: Пустые значения
- **WHEN** значения обоих типов равны `None` или пустой строке, а общие настройки отсутствуют
- **THEN** ни для одного типа параметр reasoning не отправляется

#### Scenario: Смешанная пара наследует разные общие настройки
- **WHEN** deep использует OpenAI, quick использует Google, индивидуальный reasoning отсутствует, `openai_reasoning_effort=high` и `google_thinking_level=minimal`
- **THEN** deep получает `reasoning_effort=high`, quick получает `thinking_level=minimal`

### Requirement: Совместимость провайдеров и моделей

Система SHALL передавать разрешённое значение для OpenAI, существующих OpenAI-совместимых провайдеров и Azure как `reasoning_effort`, для Anthropic как `effort`, для Google как `thinking_level`. Приложение SHALL NOT отбрасывать параметр по имени модели, подменять его значение или вводить универсальный список допустимых значений. Непустые значения, включая строку `none`, SHALL передаваться без изменений; их принятие определяется SDK/сервером, ошибки SHALL NOT скрываться повторной отправкой без параметра. Для Bedrock новые настройки SHALL не добавлять reasoning: новый протокол настройки не вводится. Нормализация ответов, сохранение reasoning-данных для протокольного обмена и отделение reasoning от текста SHALL оставаться без изменений.

#### Scenario: Общие настройки другого провайдера
- **WHEN** фактический provider типа равен Anthropic, задана только общая настройка OpenAI и нет настройки типа
- **THEN** настройка OpenAI не используется для Anthropic

#### Scenario: Поддерживаемые провайдеры
- **WHEN** для OpenAI, Anthropic или Google явно задано непустое значение типа, в том числе для неизвестного приложению имени модели
- **THEN** значение передаётся через соответствующий параметр без фильтра по имени и без подмены

#### Scenario: OpenAI-совместимый провайдер или Azure
- **WHEN** тип использует существующего OpenAI-совместимого провайдера либо Azure и разрешён reasoning
- **THEN** значение передаётся как `reasoning_effort` независимо от имени модели

#### Scenario: Google minimal и строка none
- **WHEN** Google-модель с `pro` в имени получает `minimal`, либо любая модель с поддерживаемым параметром получает строку `none`
- **THEN** значение сохраняется буквально, а не заменяется на `low` и не интерпретируется как наследование

#### Scenario: Провайдер без текущей поддержки настройки
- **WHEN** выбран Bedrock и задан новый ключ reasoning
- **THEN** новая настройка не добавляет параметр reasoning и не меняет существующее поведение провайдера

#### Scenario: Сервер отклоняет параметр
- **WHEN** SDK или сервер отклоняет переданный reasoning
- **THEN** приложение сохраняет существующий путь обработки ошибки и не повторяет запрос с удалённым или подменённым reasoning

#### Scenario: Нормализация ответа не меняется
- **WHEN** ответ содержит текстовые и reasoning-блоки
- **THEN** применяются прежние правила нормализации и протокольного сохранения данных

### Requirement: Сохранение конфигурации в CLI

CLI SHALL сохранять индивидуальные reasoning-настройки из окружения при сборке конфигурации запуска. Существующий общий интерактивный выбор SHALL служить только резервным значением для типов без переопределения и с соответствующим фактическим провайдером. Общие настройки других провайдеров из конфигурации SHALL NOT затираться отсутствующим интерактивным выбором. Существующие правила пропуска общего запроса SHALL сохраняться; новые отдельные запросы для deep и quick не требуются.

#### Scenario: Интерактивное резервное значение
- **WHEN** обе модели используют OpenAI, в окружении deep=`high`, quick не задан и пользователь выбирает общую настройку `medium`
- **THEN** запуск использует deep=`high`, quick=`medium`

#### Scenario: Неинтерактивная настройка
- **WHEN** общий провайдер и обе настройки типов заданы окружением
- **THEN** CLI сохраняет обе настройки без дополнительных запросов reasoning

#### Scenario: Настройка второго провайдера сохраняется
- **WHEN** общий интерактивный выбор относится к OpenAI, quick использует Google и `google_thinking_level` задан конфигурацией
- **THEN** запуск сохраняет Google-настройку и применяет её к quick при отсутствии индивидуального reasoning

### Requirement: Неизменность выбора моделей

Добавление только reasoning SHALL не менять встроенные модели, значения `TRADINGAGENTS_DEEP_THINK_LLM` и `TRADINGAGENTS_QUICK_THINK_LLM`, распределение агентов между типами, разрешённые провайдеры и endpoints либо прочие параметры генерации. Индивидуальные provider/URL SHALL изменяться только соответствующими настройками подключения, а не reasoning.

#### Scenario: Изменён только reasoning
- **WHEN** к существующей конфигурации добавлены только настройки reasoning
- **THEN** модели, назначения агентов, разрешённые подключения и остальные параметры запуска остаются прежними
