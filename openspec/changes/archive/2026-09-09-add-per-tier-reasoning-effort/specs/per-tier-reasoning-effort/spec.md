## Purpose

Позволить независимо управлять уровнем усилий модели при рассуждении для deep и quick, сохраняя действующие общие настройки провайдера и выбор моделей.

## ADDED Requirements

### Requirement: Независимые настройки двух типов

Система SHALL поддерживать необязательные Python-ключи `deep_think_reasoning_effort`, `quick_think_reasoning_effort` и соответствующие переменные окружения `TRADINGAGENTS_DEEP_THINK_REASONING_EFFORT`, `TRADINGAGENTS_QUICK_THINK_REASONING_EFFORT`. Значения по умолчанию SHALL быть `None`; отсутствие ключа, `None` и пустая строка SHALL означать наследование, а не отключение reasoning.

#### Scenario: Разные значения из окружения
- **WHEN** для OpenAI заданы deep=`high` и quick=`low` через новые переменные окружения
- **THEN** deep использует `high`, а quick использует `low`

#### Scenario: Программная конфигурация
- **WHEN** Python-конфигурация задаёт разные значения новых ключей
- **THEN** каждый тип использует собственное значение так же, как при настройке через окружение

### Requirement: Независимое наследование общего значения

Система SHALL разрешать reasoning отдельно для каждого типа в порядке: непустое значение типа, непустая существующая настройка активного провайдера, отсутствие параметра в запросе. Общими настройками SHALL оставаться `openai_reasoning_effort`, `anthropic_effort` и `google_thinking_level` для соответствующих провайдеров.

#### Scenario: Переопределён только deep
- **WHEN** deep=`high`, quick не задан, а общая настройка OpenAI равна `medium`
- **THEN** deep использует `high`, quick использует `medium`

#### Scenario: Переопределён только quick
- **WHEN** quick=`low`, deep не задан и общая настройка не задана
- **THEN** quick использует `low`, а для deep параметр reasoning не отправляется

#### Scenario: Существующая конфигурация
- **WHEN** новые ключи отсутствуют, но общая настройка активного провайдера задана
- **THEN** оба типа используют эту общую настройку как до изменения

#### Scenario: Пустые значения
- **WHEN** значения обоих типов равны `None` или пустой строке, а общая настройка отсутствует
- **THEN** ни для одного типа параметр reasoning не отправляется

### Requirement: Совместимость провайдеров и моделей

Система SHALL передавать разрешённое значение для OpenAI как `reasoning_effort`, для Anthropic как `effort`, для Google как `thinking_level`. Система SHALL сохранять существующие ограничения поддержки моделей и преобразования значений; для остальных провайдеров новые настройки SHALL не добавлять параметров reasoning. Допустимые значения SHALL определяться текущей поддержкой выбранного провайдера и модели, а не новым универсальным списком.

#### Scenario: Общие настройки другого провайдера
- **WHEN** активен Anthropic, задана только общая настройка OpenAI и нет настройки типа
- **THEN** настройка OpenAI не используется для Anthropic

#### Scenario: Поддерживаемые провайдеры
- **WHEN** для поддерживающей reasoning модели OpenAI, Anthropic или Google задано значение типа
- **THEN** оно передаётся через соответствующий параметр с сохранением существующих преобразований адаптера

#### Scenario: Провайдер без текущей поддержки настройки
- **WHEN** активен провайдер вне OpenAI, Anthropic и Google и задан новый ключ
- **THEN** новая настройка не добавляет параметр reasoning и не меняет существующее поведение провайдера

### Requirement: Сохранение конфигурации в CLI

CLI SHALL сохранять новые настройки из окружения при сборке конфигурации запуска. Существующий общий интерактивный выбор SHALL служить только резервным значением для типов без переопределения. Существующие правила пропуска общего запроса SHALL сохраняться; новые отдельные запросы для deep и quick не требуются.

#### Scenario: Интерактивное резервное значение
- **WHEN** в окружении deep=`high`, quick не задан и пользователь выбирает общую настройку `medium`
- **THEN** запуск использует deep=`high`, quick=`medium`

#### Scenario: Неинтерактивная настройка
- **WHEN** провайдер и обе настройки типов заданы окружением
- **THEN** CLI сохраняет обе настройки без дополнительных запросов reasoning

### Requirement: Неизменность выбора моделей

Добавление reasoning SHALL не менять встроенные модели, значения `TRADINGAGENTS_DEEP_THINK_LLM` и `TRADINGAGENTS_QUICK_THINK_LLM`, распределение агентов между типами, общий провайдер и endpoint либо прочие параметры генерации.

#### Scenario: Изменён только reasoning
- **WHEN** к существующей конфигурации добавлены только новые настройки reasoning
- **THEN** модели, назначения агентов и остальные параметры запуска остаются прежними
