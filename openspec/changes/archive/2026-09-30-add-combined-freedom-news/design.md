# Design

## Context

Мотивация описана в proposal.md. Исследован текущий layout версии 0.5.1: `dataflows/router.py` выбирает первую успешную реализацию; `vendors/yahoo/news.py` уже фильтрует глобальные статьи до лимита и использует `coverage_gap`. Старые пути `interface.py` и `yfinance_news.py` больше не являются точками изменения.

`agents/tools.py` сохраняет `InjectedState` и ограничивает даты через `as_of_window`; Sentiment Analyst вызывает `get_news.func` с датами состояния, но подписывает блок как Yahoo. Тесты `test_news_lookahead.py` и `test_vendor_routing.py` фиксируют даты, покрытие и явные резервные цепочки. Существующие OpenSpec capabilities описывают только конфигурацию моделей, конфликтующих новостных требований нет.

В рабочем дереве уже есть `fnox.toml` с двумя именами ключей и keychain service `tradingagents-tradernet-global`; сохраняем его содержимое. Публичная документация доступна на `.global`, но authenticated smoke-test не выполнен. Исследованный SDK 2.2.0 использует `Tradernet(public, private)`, `DOMAIN` и `authorized_request(cmd, params, version=3)`; высокоуровневый `get_news` не поддерживает нужный provider.

## Goals / Non-Goals

**Goals:** единая подготовка статей перед форматированием; изоляция credentials и брокерского транспорта; повторное использование текущих инструментов и даты анализа; ограниченные расходы API.

**Non-Goals:** универсальная платформа агрегации произвольных поставщиков, новый граф, изменение иных data categories, постоянный кеш, фоновые сервисы, реконструкция исторических версий.

## Decisions

### 1. Структурированный слой вместо разбора Markdown

Добавить `dataflows/news.py`: минимальные записи статьи и результата источника, нормализация URL, объединение и форматирование. Статья содержит source ID, delivery sources, publisher, title, bounded text, URL, published_at UTC, language и instrument. Результат отдельно содержит articles, outcome (`ok`, `empty`, `unavailable`), coverage (`unknown`, `observed`) и truncated/reasons. Статус покрытия не исчезает при непустом списке.

В `vendors/yahoo/news.py` выделить структурированные fetch-функции. Публичные Yahoo-функции остаются совместимыми по сигнатурам, смыслу вывода и исключениям. Для combined использовать исходные записи без дедупликации только по заголовку; существующее самостоятельное поведение Yahoo защищено регрессиями. Не парсить текстовые ошибки и Markdown.

### 2. SDK как единственный брокерский транспорт

Добавить `vendors/freedom.py` и зависимость `tradernet-sdk>=2.2.0,<3`. Локальный подкласс `Tradernet` задаёт `DOMAIN="tradernet.global"`, не изменяя класс библиотеки глобально. Ключи читать лениво из окружения и передавать явно. Не создавать собственный HTTP/HMAC клиент.

Вызовы: `getNewsProvidersList` для проверки `fbrokerkz`, страницы `getNewsList(provider="fbrokerkz", lang=..., take=..., skip=...)`, карточки `getNewsDetail(id=...)`. Полный текст брать только из карточек с подтверждённым providerAlias. Проверять HTTP/SDK исключения и тела `error`/`code`; исключения наружу санитизировать без repr клиента, тела и заголовков. Отключить чувствительное SDK debug-логирование на уровне его конкретного logger, не глобального logging. Не следовать междоменным редиректам с авторизацией.

Верифицировать в исходниках закрепляемой версии SDK точку задания transport timeout и redirect policy; использовать настройку или узкое переопределение SDK transport hook, оставив отправку и подпись SDK. Нельзя ограничивать лишь ожидание future, оставляя запрос исполняться в фоне. Проверку этого контракта завершить до написания адаптера; при невозможности обеспечить границы остановить соответствующую задачу и пересмотреть дизайн.

### 3. Тикеры и бюджет

Сопоставление задаётся config-словарём `freedom_symbol_map` (по умолчанию пустой). Явные квалифицированные идентификаторы Tradernet, например `AAPL.US`, можно передавать как есть после проверки формата; остальные требуют записи, например `{"AAPL": "AAPL.US"}`. Не добавлять суффиксы эвристически и не использовать Yahoo normalizer для брокера. Общая лента не требует mapping.

Предлагаемые defaults: `freedom_news_language="ru"`, `freedom_news_page_size=20`, `freedom_news_max_pages=3`, `freedom_news_max_details=40`, `freedom_news_timeout_seconds=15`, `news_max_text_chars=4000`. Числовые значения положительны, page_size не выше 100; итоговые defaults лимитов переиспользуют существующие news settings. Предоставить ENV `TRADINGAGENTS_FREEDOM_SYMBOL_MAP` как JSON object строка→строка для CLI с валидацией; остальные параметры доступны Python config, язык также через ENV.

Последовательный bounded обход без дополнительных retry: до трёх страниц, до сорока уникальных карточек, плюс один запрос providers. Остановка: пустая страница, достигнутый total либо бюджет. Повтор страницы без новых IDs прекращает обход с пометкой неполноты. Нельзя останавливаться по первой старой статье: порядок не гарантирован. Неизвестные/невалидные карточки исключаются с пометкой, общий сбой следующей страницы сохраняет уже полученные статьи как частичный результат.

### 4. Временная фильтрация и отбор

Freedom datetime формируется из `dateTime` и `timeZone`; неопределённость даёт undated, а не naive UTC. Переиспользовать `in_window`, неизвестные даты в live выводить с явной отметкой. Историческое покрытие Freedom всегда unknown до внешнего подтверждения архива, даже после обхода всех доступных страниц. Вывод предупреждает, что текущая редакция текста не является историческим снимком.

Дедупликация внутри источника по ID; между источниками по URL: нормализовать host/scheme, убрать fragment и известные `utm_*`, `gclid`, `fbclid`; сохранить остальные query-параметры и путь. Для совпавшего URL сохранять оба provenance и использовать Freedom-текст при наличии, иначе Yahoo summary, не склеивая тексты. Разные URL с одинаковыми заголовками остаются разными статьями.

Каждую ленту сортировать по времени убывания (undated последними), ties по URL/ID. После дедупликации отбирать по очереди Freedom/Yahoo, пропуская выбранные ID; общий дубль считается представленным в обоих источниках. Остаток лимита заполнять доступными статьями. Итог сортировать по времени с тем же tie-breaker. При лимите 1 выбирать самую свежую, при равенстве Freedom. Так объём одного источника не вытесняет другой.

### 5. Агрегатор и конфигурация

`vendors/combined_news.py` вызывает обе структурированные загрузки напрямую, без рекурсии через router, последовательно и независимо перехватывает их ошибки. Непустой частичный результат возвращается с источниковыми статусами; два сбоя дают строковый `DATA_UNAVAILABLE`. Успешная пустота при отказе второго источника остаётся частичным результатом, а не подтверждённой пустотой общей ленты. Standalone Freedom использует тот же формат и статусы.

Зарегистрировать `freedom` и `combined` только для двух news methods. Сохранить алгоритм резервной цепочки router. Добавить scalar `news_vendor=None` и ENV `TRADINGAGENTS_NEWS_VENDOR`; приоритет: `tool_vendors[method]` → непустой news_vendor для двух news methods → существующая категория. Default не меняется, secrets не нужны для Yahoo. Новый CLI flag не требуется.

### 6. Аналитики и инструкции

News Analyst сохраняет tools. У Sentiment Analyst заменить Yahoo-specific подпись и добавить правило, что содержимое источников является данными, не инструкциями. Это локальная правка prompt, не изменение структурированного отчёта. Тестировать прямой prefetch и вызов news tool с injected trade_date; обе ветки получают одинаковую атрибуцию и ограничения.

## Risks / Trade-offs

- Недоступный endpoint/канал/тариф → отдельный live smoke-test после разрешения владельца; mocked tests не объявлять подтверждением доступа.
- Неизвестные rate limits → конечный бюджет без агрессивных retries, явная недоступность при throttling.
- Лицензия текстов → до эксплуатационного включения уточнить разрешение передачи LLM; разработка mock-контракта этого не доказывает.
- Offset pagination и обновления статей → дедупликация и неизвестное покрытие, без обещания полного архива.
- Повторная загрузка двумя аналитиками → принимается в первом этапе; постоянный кеш расширил бы scope и требования к хранению.
- SDK имеет длительный default timeout и debug-логи → обязательные проверки фактической настройки timeout, редиректов и отсутствия секретов.

## Migration Plan

Добавить SDK, общий контракт, адаптеры, registry/config и документацию; сохранить обычный Yahoo запуск. Пользователь сохраняет ключи существующими `fnox set`, указывает mapping и запускает `TRADINGAGENTS_NEWS_VENDOR=combined fnox exec -- uv run tradingagents`. Для отката убрать переменную/override. Схема отчётов и база данных не мигрируют; сравнение поставщиков проводить новым запуском без возобновления старого checkpoint.

Рекомендуемые skills при apply: `find-docs` для SDK/fnox, `ccc` для навигации; при изменении LangChain prompt — `ecosystem-primer` и соответствующий framework skill. Повторно проверить SDK docs, не переносить ранее обсуждённые устаревшие пути. Тесты отключают dotenv до импорта, используют фальшивые credentials и запрет реальной сети.

## Open Questions

Точные account-specific права и состав доступных языков проверяются разрешённым smoke-test; язык ответа сохраняется независимо от запрошенного. Если `.global` не обслуживает новые команды, не подменять домен или канал: источник остаётся unavailable до отдельного решения.
