# Design

## Context

Мотивация и границы изменения описаны в `proposal.md`; поведение — в `specs/freedom-portfolio-valuation/spec.md`.

Наблюдения по исходникам и предыдущему исследованию:

- `tradingagents/portfolio.py` содержит брокер-нейтральный `PortfolioContext`: `cash`, одна `currency`, позиции с `quantity` и необязательной `average_price`. `position_in` возвращает первое совпадение без учёта регистра. Рыночной стоимости и валюты каждой позиции в этой схеме нет. Методы и схему не меняем.
- `tests/test_portfolio_context.py` закрепляет различие между отсутствующим контекстом и пустым портфелем, JSON-загрузку, отображение и влияние портфеля на checkpoint-подпись.
- `tradingagents/dataflows/vendors/freedom.py` и `docs/tradernet-sdk.md` задают рабочий шаблон SDK-подкласса: фиксированный домен, timeout, запрет редиректов, отключённое логирование подписанных запросов и безопасные ошибки. Не импортируем приватный `_NewsTradernet` и не рефакторим новостной код ради нового модуля.
- `pyproject.toml` уже содержит `tradernet-sdk>=2.2.0,<3`; поддерживается Python 3.10+. SDK 2.2.0 подписывает API v3 и по умолчанию использует `freedom24.com`, поэтому домен переопределяем локальным подклассом.
- Живое исследование подтвердило `result.ps.loaded`, `result.ps.pos`, `result.ps.acc`, API v3 и отсутствие `market_value` у RP-позиций. Публичный код терминала `https://tradernet.global/javascripts/app/PortfolioPosition.js` использует типы REPO/swap `{8, 9, 10, 14, 18}`, собственную цену для них и абсолютную стоимость. Это внешний исследованный источник, не стабильный контракт библиотеки; поддержка фиксируется офлайн-тестами, неизвестные типы не угадываются.

Официальные описания: `https://tradernet.global/tradernet-api/get-example?id=portfolio-get-changes` и `https://tradernet.global/tradernet-api/get-example?id=quotes-get`. Старый пример V2 не заменяет подтверждённый путь SDK v3. Реальный счёт, суммы, account key и полные ответы не включаем в файлы проекта.

Для реализации полезны skills `find-docs` для перепроверки SDK-контракта, `ccc` для поиска существующих точек совместимости и `openspec-apply-change` после отдельного разрешения на реализацию. Существующие шаблоны спецификаций — `openspec/specs/combined-broker-news/spec.md`; тестового транспорта — `tests/test_freedom_news.py`.

## Goals / Non-Goals

**Goals:**
- Разделить чтение, десятичную оценку и совместимое представление по зависимостям: отдельный брокерский пакет вне TradingAgents и небольшой адаптер внутри приложения.
- Сделать статус неполноты и выбор источника цены частью результата, а не неявным условием в вызывающем коде.
- Обеспечить явную конвертацию в `PortfolioContext`, не расширяя его одно-валютную схему и не теряя владения.

**Non-Goals:**
- Многоброкерный универсальный слой, автоматическое получение всех счетов, опционные и фьючерсные модели оценки.
- FX-конвертация, изменение глобальных настроек, наследование от `PortfolioContext`, автоматический экспорт на диск, CLI или инструмент для LLM.
- Подстановка текущего портфеля в исторический анализ или объявление оценки доступными к выводу средствами.

## Decisions

### 1. Отдельный брокерский пакет и три явных операции

Разместить пакет `tradernet_global/` в корне репозитория, а не внутри `tradingagents/`. Имя с подчёркиванием пригодно для Python-импорта; домен HTTPS остаётся строго `tradernet.global`. Не создавать новую репозиторию или отдельный проект сборки. Расширить `tool.setuptools.packages.find.include` на `tradernet_global*`; новых зависимостей не требуется.

Разделение файлов по ответственностям:

- `tradernet_global/models.py`: результаты и безопасные ошибки оценки/получения.
- `tradernet_global/valuation.py`: чистая проверка снимка и арифметика.
- `tradernet_global/client.py`: узкий SDK-транспорт и явное чтение.
- `tradernet_global/__init__.py`: публичные экспорты брокерского API, без импорта TradingAgents.
- `tradingagents/freedom_portfolio.py`: только преобразование в существующий `PortfolioContext` и безопасная ошибка конвертации, без ключей, SDK-транспорта или арифметики оценки.

Предусмотреть публичные операции:

- `value_freedom_portfolio(snapshot, quotes, *, fetched_at, quotes_fetched_at=None) -> FreedomPortfolioValuation`: чистый расчёт из SDK-подобных словарей. `quotes` — словарь по точному тикеру, время передано вызывающим кодом, без чтения часов внутри расчёта.
- `fetch_freedom_portfolio(*, client=None, timeout_seconds=15, quote_batch_size=50) -> FreedomPortfolioValuation`: получить снимок и ограниченные пакеты котировок, затем вызвать чистый расчёт. Параметры явно проверяются; размер пакета 1–100, timeout — конечное положительное число, не bool.
- `tradingagents.freedom_portfolio.to_portfolio_context(valuation, *, cash_currency=None) -> PortfolioContext`: адаптация в существующий формат, без сетевых запросов и записи файлов. Первые две операции экспортируются из `tradernet_global`.

Альтернатива — расширить `PortfolioContext` рыночными полями и валютами позиций. Отклонено: это меняет JSON, checkpoint-подписи и смысл входных данных всего графа. Наследование тоже не решает различие между свободными деньгами и стоимостью активов.

### 2. Небольшие типизированные результаты

Использовать dataclass из стандартной библиотеки, без новых зависимостей:

- `PositionValuation`: индекс строки, `position_id` при наличии, тикер, имя, тип, валюта, `quantity: Decimal | None`, `price`, коэффициент, купон, `value: Decimal | None`, `method`, `price_source`, доступное время источника, предупреждения/причина. Не хранить сырой ответ или account key.
- `CashBalance`: индекс строки, валюта, `amount: Decimal | None`, причина недоступности.
- `CurrencyTotal`: валюта, известные суммы позиций и cash, `known_subtotal`, `total: Decimal | None`, `complete`, перечень недоступных индексов.
- `FreedomPortfolioValuation`: позиции, денежные строки, `totals_by_currency`, `complete`, времена получения портфеля/котировок в UTC, безопасные предупреждения.
- `FreedomPortfolioError` в брокерском пакете: безопасная ошибка получения/структуры данных; `PortfolioContextConversionError` в адаптере TradingAgents: безопасная ошибка конвертации. Ошибки не содержат исходное тело, ключи, заголовки или account key; внешние исключения не показываются в цепочке (`raise ... from None`).

Достаточно `Decimal(str(value))` для конечных int/float/строк, но bool, пустые строки, `NaN` и бесконечности отвергаются. Потерю точности исходного JSON float не скрываем. Суммы считаются без промежуточного округления, отображение до двух знаков в примерах — `ROUND_HALF_UP`, не изменение хранимой оценки. Результаты не являются публичным JSON-протоколом; для совместимого JSON используется существующий `PortfolioContext.model_dump_json()`.

Альтернатива — обычные словари и float. Отклонено: неявные валюты, пропуски и двоичная арифметика затрудняют проверку итогов.

### 3. Валидация и полнота

До запросов котировок проверить успешный словарь без error envelope и `loaded is True`, коллекции `pos` / `acc` как списки словарей, непустые строковые валюты и тикеры. При невозможности связать строку с валютой либо разобрать коллекцию — безопасная ошибка всего снимка. Некорректное количество, сумма, тип или цена в идентифицируемой строке сохраняются как недоступность этой строки, а не ноль.

Сохранять порядок исходных строк, включая нулевые количества; идентификаторы позиций не заменять account key. Дубли не удалять. Для каждой валюты суммировать только известные значения; `total` определён только при полной оценке всех её строк. Пустой загруженный портфель — `complete=True`, пустые итоги. Наличие котировочных предупреждений само по себе не запрещает полный денежный итог, если все позиции имеют допустимую резервную оценку; `complete` означает числовую полноту, не свежесть или гарантированную реализуемость.

Альтернатива — возвращать только сумму найденных значений. Отклонено: пользователь может принять подытог за весь портфель.

### 4. Правила оценки без скрытой нормализации

Поддерживаемый набор: обычные акции `t=1`, облигации `t=2`, REPO/swap `t in {8,9,10,14,18}`. Проверять целочисленный код, не bool и не суффикс. Не применять Yahoo-нормализацию, не удалять `_RP` и не запрашивать базовую акцию для RP. Прочие типы — недоступность с `unsupported_type`. Если непустая `base_currency` отличается от `curr`, оценка недоступна (`currency_conversion_required`), FX не выполняется. Для строк с нулевым количеством достаточно допустимых типа и валюты; цена и купон не нужны.

Выбор положительной конечной цены для акций/облигаций:

1. Открытый рынок: при `q>0` порядок `bbp`, `ltp`, `bap`; при `q<0` — `bap`, `ltp`, `bbp`.
2. Закрытый рынок: `ltp`.
3. Неизвестный статус рынка: не угадывать сторону, перейти к собственной `mkt_price` снимка с предупреждением.
4. Нет допустимой котировки: собственная `mkt_price` снимка, источник `portfolio_fallback`; если её нет — недоступность.

Считать `value = (price × factor / 100 + accrued_interest) × quantity`. Для обычных акций: factor=100 и купон=0. Для облигаций: `fv` позиции, иначе `fv` соответствующей котировки; только конечное положительное значение, без безусловного default=100. Купон: явный допустимый `quote.acd` имеет приоритет, иначе `position.accruedint_a`; пропуск отличается от нуля, а явно некорректное значение не маскируется fallback. Для цены снимка без котировки купон берётся из снимка. Поле `market_value` не складывать дополнительно: его семантика относительно купона не гарантирована.

Для REPO/swap: собственная `position.mkt_price`, обязательный допустимый `position.fv` и `position.accruedint_a`; `value = abs((price × fv / 100 + accrued_interest) × quantity)`. Отсутствующий коэффициент/купон не угадывать. Отсутствие цен RP в котировочном ответе не является причиной запрашивать базовую акцию.

Время последней сделки хранить отдельно от времени получения. Если timezone однозначен (`UTCOffset` котировки — минуты), нормализовать в UTC; иначе сохранить исходное время как неподтверждённое, не присваивать UTC. Не вводить необоснованный порог «свежести» и не обещать актуальную сделку для закрытого рынка.

Альтернатива — умножить суммарное RP-количество на цену FRHC или суммировать `market_value`. Отклонено: RP имеют собственную оценку, а `market_value` может отсутствовать и не определяет включение купона.

### 5. Узкий SDK-транспорт, без рефакторинга новостей

Локальный приватный подкласс `Tradernet` с `DOMAIN="tradernet.global"`; ключи из существующего окружения при создании клиента. Вызвать `account_summary()` и `get_quotes()`; оставить подпись и сериализацию SDK. В `authorized_request` разрешить только `getPositionJson` и `getStockQuotesJson`, version=3; в `request` проверять точные HTTPS URL этих команд и POST. Иные команды отклонять до сети. Сессия `HTTPSession`, timeout на запрос, `allow_redirects=False`, любой 3xx — отказ. Отключить только logger этого подкласса, не глобальное логирование приложения.

Запросить уникальные точные тикеры только поддерживаемых ненулевых обычных акций/облигаций, которые не требуют FX. Разбить на пакеты фиксированного размера. Каждый пакет отправляется не более одного раза, автоматических повторов и смены домена нет. Число запросов равно одному снимку плюс `ceil(N / quote_batch_size)` для N таких уникальных тикеров. Неограниченной пагинации нет; конечность обеспечена составом полученного снимка и ограниченными пакетами. При ошибке пакета продолжить остальные и обозначить недоступность котировок этого пакета; всё равно вызвать чистый оценщик.

`client` предназначен для подставного SDK-совместимого клиента и явного управления вызывающим кодом; созданный внутри клиент закрывается в `finally`, переданный не закрывается. Гарантии фиксированного транспорта относятся к созданному модулем клиенту; переданный клиент — ответственность вызывающего кода. Созданный модулем клиент, ключи и сырой ответ не возвращаются. SDK/HTTP исключения заменяются фиксированными кодами ошибок; статус HTTP можно включать без тела ответа. Импорт `tradernet_global` не загружает TradingAgents или его dotenv-настройки. Импорт адаптера на стороне TradingAgents сохраняет существующую загрузку dotenv приложением, но не добавляет доступа к брокерским ключам на импорте.

Альтернатива — выделить общий transport из новостного адаптера. Отклонено для этого change: небольшой повтор защищённого SDK-hook дешевле несвязанного рефакторинга существующего поведения. Альтернатива — собственный HMAC-клиент; отклонена, SDK уже обеспечивает подписанный доступ.

### 6. Адаптация в PortfolioContext без ложных фактов

Адаптер `tradingagents/freedom_portfolio.py` импортирует результаты из `tradernet_global` и создаёт существующие `PortfolioContext` и `Position`. Обратная зависимость брокерского пакета на TradingAgents запрещена. Все позиции, включая неизвестную стоимость и нулевые количества, передаются. Для повторяющихся полных тикеров группировать по `ticker.upper()` в порядке первого появления и суммировать знаковые количества, сохраняя первое исходное написание; разные RP-суффиксы никогда не объединять. Подробные строки оценки не изменяются. Все `average_price=None`: текущая цена не является ценой входа; извлечение корректной средней цены входа разных типов не входит в изменение.

При `cash_currency=None`: если в портфеле ровно одна валюта, выбрать её; при нескольких либо отсутствии валют установить `cash=None`, `currency=None`. Нулевые остатки других валют считаются присутствием валюты, а не разрешением скрытой конвертации. При явном `cash_currency` выбрать только присутствующую валюту; неподтверждённая/неизвестная валюта или недоступные cash-строки приводят к безопасной ошибке конвертации. Для выбранной валюты суммировать только `acc[].s`, не `forecast_*` и не `t2_*`; отсутствие cash-строк при наличии позиций этой валюты трактуется как неизвестный cash (`None`), не ноль. Все позиции других валют сохраняются с `average_price=None`, так что одно-валютный `currency` не подписывает ложные цены входа.

Неизвестное количество любой позиции запрещает конвертацию всего портфеля; неизвестная рыночная оценка при известном количестве не запрещает её. Decimal → float только на границе существующей схемы: проверить конечность, переполнение и ненулевое значение, потерянное до нуля; обычную ограниченную точность float явно документировать. Суммы и количества в подробной оценке остаются Decimal. JSON принимается существующим `load_portfolio`, `render` и `fingerprint` работают без изменений; `fingerprint` остаётся подписью владений/cash, а не оценки рынка.

Альтернатива — передать часть позиций выбранной валюты. Отклонено: `position_in` мог бы объявить существующее иностранное владение отсутствующим. Альтернатива — заполнить `cash` всем итогом и `average_price` текущей ценой; отклонена как подмена смысла существующей схемы.

## Risks / Trade-offs

- [SDK и формат типов могут измениться] → поддерживаемый набор и envelopes закрепить тестами, неизвестное обозначать недоступным; зависимость оставить в существующем диапазоне.
- [Портфель и котировки получены не атомарно] → отдельные времена получения, источники и предупреждения; не обещать биржевой расчёт net liquidation или доступную сумму вывода.
- [Тип REPO имеет специальные правила брокера] → использовать проверенную формулу терминала для явных кодов, не подменять цену базовым инструментом; новые виды не угадывать.
- [Неоднозначные коэффициенты, купоны или валюты] → неполный итог, не нулевая/приблизительная скрытая оценка.
- [Контекст теряет Decimal-точность и детали строк] → потери ограничены явной совместимой конвертацией; подробный результат остаётся источником оценки и полноты.
- [PortfolioContext не содержит даты и валют отдельных позиций] → только явный вызов конвертации, все цены входа неизвестны, документация запрещает выдавать текущий снимок за исторический контекст.
- [Разрешения ключей шире команд модуля] → локальный список разрешённых запросов не объявлять серверным ограничением ключа; тестировать отказ до сети.
- [Тестовая среда случайно читает реальный счёт] → подставные клиенты/ключи, блокировка sockets, `PYTHON_DOTENV_DISABLED=1`; живая проверка не является условием CI.

## Migration Plan

Изменение аддитивное: новый пакет в существующем дистрибутиве, адаптер и документация без миграции схем, конфигурации или сохранённых данных. Сначала выполнить офлайн-проверки расчёта, транспорта и совместимости, затем проверить содержимое wheel и независимый импорт установленного пакета вне исходного дерева. Сохранить неизменными существующие тесты `test_portfolio_context.py` и `test_freedom_news.py`. Откат — прекратить вызов нового API; существующий анализ и `PortfolioContext` не затронуты. Новую живую проверку выполнять только с отдельным разрешением пользователя, без сохранения приватных ответов.
